# TuneQueue 🎧

**Сонг-реквесты для Twitch на Spotify. Без подписок и хуйни.**

> 🇬🇧 [English](README.md)

> ### ⭐ Основное направление — расширение для браузера
>
> **[extension/](extension/)** — зритель пишет `!sr <ссылка>` в Twitch-чат, расширение
> жмёт кнопку «Добавить в очередь» в открытом веб-плеере Spotify. Без API, Premium и серверов.
> Подробно: [extension/README.md](extension/README.md).
>
> Десктоп-приложение ([desktop/](desktop/)) — в архиве: работало, но воровало фокус окна
> и дублировало очередь Spotify. Код оставлен для истории.
>
> Веб-версия ниже — ранний прототип (веб-сервис с OAuth + Premium/плейлист).

Зрители пишут `!play` в чат Twitch — трек встаёт в очередь и уходит прямо в твой плеер
Spotify. Всё управление — с одного дашборда.

- 🎧 **Бесплатно и открытый код** (MIT). Свой инстанс или общий — никто ничего не платит.
- 💬 **Команды в чате**: `!play`, `!queue`, `!np`, `!skip` (только моды).
- 🎛 **Дашборд**: живая очередь, что играет, пропуск/пауза/очистка, история запросов.
- 🔗 **Просто подключить**: вводишь ник канала, линкуешь Spotify через OAuth (PKCE),
  бот сам заходит в чат. Ни конфигов, ни серверов поднимать не надо.
- 🧩 **Мульти-тенант**: один процесс обслуживает много стримеров (одно IRC-соединение,
  очереди на каждый канал).

## Требования

| Что | Зачем |
|---|---|
| **Spotify Premium** (подключаемого аккаунта) | Официальный Spotify API разрешает управление очередью/плеером только с Premium. Это ограничение Spotify — обойти его легально нельзя. |
| Бесплатное приложение Spotify Developer | OAuth (создаётся один раз в [Developer Dashboard](https://developer.spotify.com/dashboard)). |
| Аккаунт Twitch-бота *(опционально)* | Без токена бот всё равно **читает** чат и выполняет команды, просто не может отвечать в чате. С токеном — отвечает. |

## Быстрый старт

```bash
git clone <url-репозитория> tunequeue && cd tunequeue
npm install
cp .env.example .env      # заполни SPOTIFY_CLIENT_ID
npm run dev:web           # терминал 1 → фронтенд на :5173
npm run dev               # терминал 2 → API + бот на :8787
```

Открой http://localhost:5173, введи свой Twitch-ник, нажми **Подключить Spotify**.

**В настройках приложения Spotify** добавь redirect URI: `${BASE_URL}/api/spotify/callback`
(для dev: `http://localhost:5173/api/spotify/callback`).

### Продакшн

```bash
npm run build             # фронтенд собирается в dist/
npm start                 # один процесс: API + фронтенд на :8787
```

Задай `BASE_URL` — публичный адрес. За обратным прокси с TLS (Caddy, nginx…),
каталог `data/` — на постоянный диск (SQLite). Спокойно живёт на любом дешёвом VPS.

## Команды в чате

| Команда | Кто | Что |
|---|---|---|
| `!play <название или ссылка Spotify>` | все | Поиск и добавление в очередь (кулдаун 20 с на юзера, макс. 100 в очереди) |
| `!queue` | все | Показать ближайшие 5 треков |
| `!np` / `!song` | все | Что играет сейчас |
| `!skip` / `!next` | моды и броадкастер | Пропустить трек |

## Как это устроено

```
Чат Twitch ──► IRC-бот (ws) ──► локальная очередь (SQLite) ──► Spotify Web API ──► плеер
                    ▲                                              │
       дашборд (React) ◄── REST API (Fastify) ◄────────────────────┘
```

- Источник истины — локальная очередь; фоновый свипер (15 с) докидывает `pending`-треки
  в Spotify, как только появляется активное устройство, и сверяет статусы played/skipped.
- Если плеер офлайн в момент запроса — трек ждёт в очереди и уйдёт в Spotify автоматически,
  когда ты откроешь приложение и нажмёшь Play.
- Доступ к настройке — секретная ссылка (`/?setup=…`) в браузере. Храни как пароль.

## Решение проблем

- **«канал не найден на Twitch»** — Twitch молча игнорирует `JOIN` для несуществующих
  ников. Проверь название канала.
- **Бот не отвечает в чате** — задай `TWITCH_BOT_NICK` + `TWITCH_BOT_OAUTH` (скоупы
  `chat:read chat:edit`). Чтение и выполнение команд работают и без этого.
- **Запросы висят `pending`** — нет активного устройства Spotify или аккаунт не Premium;
  открой Spotify и раз нажми Play.
